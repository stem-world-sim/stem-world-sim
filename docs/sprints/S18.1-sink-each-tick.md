# Sprint 18.1 — a step includes its water

**Status:** locked for oracle
**Depends on:** S18.
**Does not change:** rate magnitudes (`E_OPEN`, `E_SOIL`, `P_MAX`), stress thresholds, catalog, ci.yml.

## Problem

With tick = 1 day, pond and soil moisture jump on the 9th and 10th day and sit still between. That is `N_ET = 10`: evaporation and uptake run only when `clock.tick % 10 == 0`. Hydro runs every tick, but a settled tile has no hydro left to do.

A day of pond water does evaporate. A step of length `dt` must apply that step's sinks, not wait for a batch.

The page also shows a tick count. A tick is no longer one unit. Show elapsed time only.

## Deliver

Live `tick`:

- Hydro, then evaporation, then uptake, every tick.
- Scale those by `tick_dt` as S18 already does.
- `N_ET` does not gate sinks. It may stay as a constant. It must not decide whether water leaves this tick.

`catch_up(K)`:

- K blocks, each the same work as one live tick at the current `dt`.
- Clock advances by K, not `K * N_ET`.
- A live run of K ticks and `catch_up(K, 0)` agree on pond, θ, and elapsed time for a settled tile.

Critic:

- Drop the tick count from the page and from event lines.
- Show elapsed time only (`sim_time_s`, formatted).
- The K control is still "advance K steps." The header does not say how many steps have run.

Page: after green, rebuild `critic.html.gz` and replace the `critic` release asset. Do not commit `dist/`. Do not edit `ci.yml`.

## Tests

- `d181_et_every_tick` — pond with no plants, tick = 1 day: pond drops on tick 1, 2, and 3. Not only on tick 10.
- `d181_catchup_matches_live` — same start: K live ticks and `catch_up(K, 0)` match pond, θ, and elapsed time.
- Prior suite green. `d18_default_dt_matches_prior_behavior` is amended if it required the 10-tick sink batch. The new rule replaces that batch.
